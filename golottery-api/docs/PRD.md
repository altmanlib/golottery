# 后端 API · 产品需求

## 1. 目标与边界

为线下活动提供多租户活动引擎：组织开通场次后创建活动，宾客在微信小程序内定位签到，主持人在 Web 大屏抽奖。后端负责身份、租户隔离、围栏判定、奖池与结果落库，客户端只提交输入并展示结果。

首发采用共享库、平台单小程序、手动开通场次。不做组织独立分库、在线支付与发票、指定中奖人、轨迹追踪。

## 2. 身份与组织

| 规则 | 要求 |
| --- | --- |
| 层级 | 平台 → 组织（org）→ 活动（event）→ 参会人/工作人员 |
| 租户隔离 | 所有业务查询限制 `org_id` / `event_id`，禁止跨组织读写 |
| 宾客 | 活动码指定活动；微信登录获取 openid；姓名与手机号后四位匹配名单，同一活动一人仅绑定一个 openid，同一 openid 可参加多场 |
| 管理员 | 邮箱与口令登录；仅管理本组织活动；工作人员按活动授权 |
| 主持人 | 活动级 host 凭证；SSE 和抽奖接口校验活动归属 |
| 平台运营 | 开通组织、授予场次配额和人数档位，查询平台用量 |
| 配额 | 创建活动消耗 1 场次；不足时拒绝；名单导入不得超过套餐人数上限 |

## 3. 活动配置与数据

- 支持创建和编辑活动、签到时间窗、围栏中心及半径、是否允许兼中、奖项名称/奖品/人数/顺序
- 生成活动码与短链；导入 Excel 参会名单，校验重复与格式错误并返回导入结果
- 导出签到名单、签到尝试明细、中奖名单及抽奖日志；坐标明细仅组织管理员可见
- 活动结束后按保留策略清理位置原始坐标：默认 30 天，可依合同调整或由组织缩短
- P1：成员管理、复制活动模板、活动结束操作和基础平台用量统计；P2：在线购买和开票

## 4. 定位签到

服务端计算活动中心与宾客位置的 Haversine 距离 `d`，使用 GCJ-02 坐标；仅当 `d - min(accuracy, 200m) ≤ radius` 时自动签到。

| 规则 | 要求 |
| --- | --- |
| 围栏 | 默认半径 400 米，管理员可设 100～1000 米，保存后立即生效 |
| 低精度 | 精度大于 500 米时返回重试提示，仍失败转人工确认 |
| 时间窗 | 窗口外拒绝签到并返回未开放或已结束 |
| 重复签到 | 同一活动名单人员只签到一次；重复请求返回既有状态与时间 |
| 人工确认 | 工作人员通过申请后视为已签到，记录处理人与方式；定位失败或超出范围可申请 |
| 审计 | 每次尝试记录坐标、精度、距离、结果、原因与时间；成功和失败都留痕 |

室内定位可能偏差几十到一百多米；伪造位置无法仅靠围栏杜绝，首发通过人工确认和现场核验补充约束。

## 5. 抽奖

仅从本活动已签到（含人工确认）人员中抽取；迟到人员下一轮入池。服务端使用 Go `crypto/rand`；前端动画不决定中奖结果。

- 默认一人只中一次；活动级 `allow_multi_win` 可允许兼中
- 支持单次抽 1 人或多人；每轮开始后冻结该轮奖池快照
- 缺席可作废并补抽；作废记录保留，已确认结果不能直接改写
- 记录奖项、奖池人数、结果、操作人、时间与作废状态，结果先落库再推送大屏
- 写接口幂等；双窗口并发抽奖不得产生重复有效中奖

## 6. 非功能要求

| 项目 | 要求 |
| --- | --- |
| 容量 | 单场签到按 100 请求/秒设计；800 人集中签到 30 分钟无系统故障 |
| 响应 | 签到服务端处理 P95 ≤ 1 秒；单轮抽奖出结果 ≤ 3 秒 |
| 安全 | 全站 HTTPS；管理和抽奖接口校验角色及活动归属；签到按 openid 每分钟 ≤ 10 次限流 |
| 弱网 | 签到、抽奖写操作幂等；大屏断线后可重新拉取状态 |
| 隐私与备份 | 定位数据按权限导出并定期清理；定期备份，提供签到名单导出以供现场兜底 |

接口定义以本项目 `api/openapi.yaml` 为准；跨端展示、授权引导和现场交互分别由 Web 与小程序实现
