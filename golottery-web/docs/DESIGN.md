# 管理端与大屏 · 技术方案

## 1. 目标与范围

使用 Vite + React 18 + TypeScript + Mantine 8 构建组织控制台与现场大屏，提供清晰的活动配置和可靠的抽奖展示。需求见 [PRD.md](PRD.md)。平台运营入口按需求规划；本方案不在浏览器里执行围栏判定、随机抽奖或租户权限裁决。

## 2. 现有结构与 API 契约

- HashRouter 管理 `#/login`、`#/console`、`#/host`；`#/*` 路径别名指向 `src/*`
- 使用 TanStack Query 管理服务端数据，Zustand 管理前端状态；Biome 统一格式和 lint
- `@hey-api/openapi-ts` 从运行中后端 `/openapi.json` 生成 `src/api-gen/`；生成代码不可手改，业务代码从生成的 SDK 和类型引用接口
- 开发态 Vite 将 `/api` 等路径代理至本地后端；生产由 Nginx 托管页面并转发 API/SSE

## 3. 控制台与运营入口

组织管理员登录后按组织展示配额、活动、名单导入导出、围栏和奖项配置；活动码可下载。创建活动、导入名单与修改围栏均以后端响应为准；不得通过前端隐藏数据代替服务端租户鉴权。

平台运营的组织开通与配额操作使用独立凭证；当对应 API 可用时实现页面，不能复用组织管理员权限。Web 展示的围栏中心与小程序使用同一 GCJ-02 坐标系。

## 4. 大屏事件流

1. 主持人以活动级凭证进入大屏；首屏拉取统计、奖项和已有中奖结果
2. 通过后端 SSE 接收 `stats`、`draw`、`void`；抽奖请求携带唯一 `requestId`，动画只负责展示已提交结果
3. 网络断开时显示错误状态；连接恢复或刷新后重拉统计和中奖结果以校正状态
4. 作废/补抽由后端接口处理；UI 保留作废状态，不直接改写已有结果

按最新 Chrome / Edge 与 1920×1080 大屏设计；现场网络应稳定。多人抽取结果分页展示，避免遮挡主持人操作。

## 5. 验证与明确不做

- 用生成的 API 类型验证数据流；测试断网重连、刷新恢复、重复触发及跨活动状态清理
- 管理端操作检查错误反馈、导入错误行、配额不足和大屏无可用奖池等边界
- 不手写重复 API 描述、不在客户端推断中奖者、不依赖前端可见性实现鉴权
