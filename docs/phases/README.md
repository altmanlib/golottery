# golottery 实施阶段

本目录把 [技术方案](../DESIGN.md) 拆成可顺序执行、可独立验收的交付阶段。每个阶段只在前一阶段门禁通过后开始。

## 1. 阶段地图

```text
阶段 1 工程基线
    ↓ 可启动、可测试的 Go API 与 Web 骨架
阶段 2 组织与活动
    ↓ 控制台登录、活动、名单、奖项
阶段 3 签到与抽奖
    ↓ 小程序签到、大屏抽奖、SSE
阶段 4 上线
      镜像、反向代理、备份
```

## 2. 阶段清单

| 阶段 | 主要交付 | 前置门禁 | 状态 |
| --- | --- | --- | --- |
| [阶段 1：工程基线](./phase-1-engineering-baseline.md) | config / store / httpapi / bizerr / auth、迁移、Web 令牌客户端 | PRD 与技术方案已发布 | 进行中 |
| 阶段 2：组织与活动 | 控制台登录、活动、名单、奖项、配额 | 阶段 1 通过 | 未开始 |
| 阶段 3：签到与抽奖 | 围栏签到、抽奖事务、SSE、小程序 | 阶段 2 通过 | 未开始 |
| 阶段 4：上线 | 镜像发版、反向代理、备份 | 阶段 3 通过 | 未开始 |

状态只允许：`未开始`、`进行中`、`已通过`、`阻塞`。阶段状态变化只修改本表。

## 3. 执行规则

1. 开始阶段前，确认前一阶段「完成定义」的所有条目均已满足
2. 阶段内先改 `openapi.yaml` 与后端实现，再生成前端 SDK，再做页面
3. 每个阶段新增自动化测试；不得把失败用例推迟到后续阶段
4. 实现中发现与设计不一致时，先更新 [技术方案](../DESIGN.md) 或 [PRD](../PRD.md)，再继续
5. 每阶段结束在 [ROADMAP.md](../ROADMAP.md) 记录提交号
