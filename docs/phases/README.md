# golottery 实施阶段

本目录按实施顺序存放阶段方案。每个阶段只在前一阶段门禁通过后开始。

## 1. 阶段地图

```text
阶段 1 工程基线
    ↓ 可启动、可测试的 Go API 与 Web 骨架
阶段 2 运营认证
    ↓ 运营账号可登录、登出、改密
阶段 3 组织与配额
    ↓ 运营可开通组织并调整场次
阶段 4 组织管理员认证
    ↓ 管理员拿到只属于该组织的 console 令牌
阶段 5 活动配置
    ↓ 活动、围栏、奖项、名单、活动码
阶段 6 现场签到
    ↓ 小程序绑定、围栏签到、人工确认
阶段 7 现场抽奖
    ↓ 大屏抽奖、作废重抽、SSE
阶段 8 品牌装修
    ↓ 对象存储、素材上传、大屏与小程序品牌位
阶段 9 上线与兜底
      镜像、备份、反向代理、离线抽奖页
```

## 3. 执行规则

1. 开始阶段前，确认前一阶段「完成定义」的所有条目均已满足，且本阶段及其他阶段标注「本阶段开工前」的开放项已有结论并写回方案
2. 阶段内先改 `openapi.yaml` 与后端实现，再生成前端 SDK，再做页面
3. 每个阶段新增自动化测试；不得把失败用例推迟到后续阶段
4. 实现中发现与设计不一致时，先更新 [技术方案](../DESIGN.md) 或 [PRD](../PRD.md)，再继续
5. 每阶段结束在 [ROADMAP.md](../ROADMAP.md) 记录提交号
6. 阶段方案使用 `phase-<n>-<slug>.md`。`n` 是实施顺序；阶段开工后编号固定、不复用，插入新阶段时只顺延未开工的阶段
7. `docs/plan/` 只用于阶段内部的临时实施笔记，不存放产品方案
8. 微信资质与域名备案周期长、不依赖代码，不受阶段门禁约束，在 [ROADMAP.md](../ROADMAP.md) 单独跟踪。阶段 5 的小程序码需要 AppID，阶段 6 真机签到需要定位接口权限，阶段 9 需要备案域名
