# 微信小程序 · 技术方案

## 1. 目标与边界

原生微信小程序 + TypeScript 实现宾客签到与现场管理入口，直接调用微信定位和位置选择 API。需求见 [PRD.md](PRD.md)。小程序只负责活动上下文、权限引导、坐标上报和结果展示；签到与抽奖结果由服务端决定。

## 2. 活动进入与身份

活动码启动参数 `e` 携带 `event publicId`；启动时存入 `app.ts` 的 `globalData.eventPublicId`。无活动上下文不开放业务页。先向后端建立活动上下文，再通过 `wx.login` 的 code 换取活动范围内的会话；宾客输入姓名和手机号后四位绑定名单，重复进入可获取既有状态。

同一微信可参与多场；切换活动必须更新会话并清理旧活动的页面状态。管理入口仅在后端授予当前活动 staff/admin 权限时展示，所有管理接口继续校验活动归属。

## 3. 定位与人工确认

1. 用户点击签到时才请求 `wx.getLocation`（`type: 'gcj02'`）；未授权时说明用途并引导打开设置
2. 上报纬度、经度与精度；服务端返回成功、重复签到、时间窗外、超范围或低精度等状态，小程序只按返回值渲染
3. 低精度提示重试一次；定位失败或超范围提供人工确认申请与进度查询
4. 工作人员查看申请，通过/拒绝并刷新统计；管理员用 `wx.chooseLocation` 选中心点并设置半径

请求超时 8 秒，失败自动重试 1 次；写操作需避免因重试产生多条有效记录。不持续采集轨迹，也不在本地推算服务端的围栏结论。

## 4. 权限、隐私与验证

`app.json` 声明 `getLocation`、`chooseLocation` 和位置权限用途；正式版需平台 AppID、备案 HTTPS 请求合法域名、定位权限及隐私指引。姓名和位置数据不跨活动缓存。

真机验证 iOS/Android 上的授权拒绝、弱定位、弱网重试、不同活动切换以及工作人员越权场景。首发不引入跨端框架、客户独立小程序或持续定位
