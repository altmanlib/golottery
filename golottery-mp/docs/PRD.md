# 微信小程序 · 产品需求

## 1. 目标与边界

平台单小程序承载多组织活动。宾客扫描活动码进入指定活动，完成身份绑定、定位签到并查看状态；活动工作人员在小程序管理入口处理人工确认和签到进度。

小程序只采集坐标与精度并展示服务端结果，不在客户端决定围栏是否通过或抽奖结果。无活动上下文时不能浏览或签到其他活动。

## 2. 宾客端

| 编号 | 功能 | 要求 | 优先级 |
| --- | --- | --- | --- |
| G1 | 活动进入与绑定 | 从活动码获得活动上下文；微信登录后输入姓名和手机号后四位匹配名单；同一活动一人仅绑定一个微信号 | P0 |
| G2 | 定位签到 | 用户点击签到才获取 GCJ-02 定位，上报坐标和精度，由服务端判定 | P0 |
| G3 | 签到状态 | 展示未签到、已签到、待人工确认及签到时间；重复点击展示既有状态 | P0 |
| G4 | 定位授权引导 | 拒绝授权时说明原因并引导打开设置 | P0 |
| G5 | 人工确认申请 | 定位失败或不在围栏内可申请并查看处理结果 | P0 |
| G6 | 中奖结果 | 展示本人奖项及兑奖说明 | P1 |
| G7 | 订阅消息 | 中奖后发送订阅消息 | P2 |
| G8 | 我的活动 | 展示当前微信参与过的活动 | P2 |

首次进入需匹配该活动名单；再打开同一活动直接展示签到状态。单人签到目标 ≤ 10 秒。请求超时按 8 秒处理，失败自动重试 1 次；写接口按幂等结果展示，避免重复操作。

## 3. 现场管理入口

| 编号 | 功能 | 要求 | 优先级 |
| --- | --- | --- | --- |
| M1 | 角色识别 | 仅向当前活动已授权的 staff/admin 展示入口；接口仍校验权限 | P0 |
| M2 | 签到进度 | 展示应到、已签到和待确认人数 | P0 |
| M3 | 人工确认 | 查看待确认申请，通过或拒绝并记录操作人 | P0 |
| M4 | 代为签到 | 按姓名搜索宾客并代为签到 | P1 |
| M5 | 围栏设置 | 使用 `wx.chooseLocation` 选中心点，输入 100～1000 米半径并保存；默认 400 米 | P0 |

定位精度超过 500 米时提示重试一次，仍失败可转人工确认；围栏外提示靠近后重试并提供人工确认入口。定位许可被拒绝时同样提供引导与兜底。现场可提示宾客优先使用手机流量。

## 4. 隐私与兼容

- 隐私指引说明收集位置与姓名；仅用户主动点击签到时获取一次位置，不持续追踪
- 位置原始数据由后端按保留策略处理；小程序不持有跨活动数据
- 支持主流 iOS / Android 微信；平台主体需配置备案 HTTPS 合法域名、定位权限和隐私声明
- 微信身份与当前活动的工作人员权限由后端校验，隐藏管理入口不能替代接口鉴权

首发不做独立客户小程序、白标 App、人脸识别或蓝牙信标
